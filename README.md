# 麦麦扭蛋机 mcd-gacha

> 设定预算、忌口和必吃项，扭出一份搭配。不满意可以单件重抽。

一个基于**麦当劳 MCP Server 真实在售数据**的随机搭配助手。

---

## 为什么做这个

面对麦当劳的菜单，普通人的真实困难不是「有什么」，而是**「我该吃什么」**：

- 60 多样在售餐品，逐个看一遍比随便点还累
- 想省钱，但不知道哪张券能用、门槛够不够
- 有忌口或想控制热量，翻菜单比计算还累
- 一个人吃饭，点多了浪费、点少了不过瘾

现有的「点餐助手」大多解决的是「更快下单」。麦麦扭蛋机换一个视角：
**先把选择收敛成一份搭配，再让你调整**。随机不是为了好玩，而是——
在 60 个选项里穷举挑选，人是算不过来��。

它给出的不是「你可能喜欢这些」，而是**一份已经满足你所有约束的组合**：
预算不超、忌口已排除、必吃项一定在、券已自动匹配。

## 目标用户

| 场景 | 需求 |
| --- | --- |
| 一个人随便吃点 | 预算 30 块、不吃辣、不想动脑 |
| 加班 / 出差落地 | 「给我一个 40 块以内的、能吃饱的搭配」 |
| 控制饮食 | 想吃麦当劳但要低卡、要高蛋白 |
| 有忌口 | 不吃辣 / 不吃海鲜 / 素食友好 |
| 多人点餐 | 3 个人 150 块，怎么配比较均衡 |

## 特性

- **真实在售数据**：菜单、优惠券、营养成分全部来自麦当劳 MCP Server，不内置任何菜单数据
- **扭蛋机交互**：拉杆下压 + 胶囊滚落动画，音效可开关（默认关），
  支持触控 / 鼠标 / 键盘，尊重系统「减少动态效果」设置
- **时段感知**：用 MCP 的 `now-time-info` 判断当前时段，揭晓时标注早餐档 / 午餐档 / 夜宵档
- **可选定位**：点地点框旁的「定位」，浏览器授权后自动填入城市名；
  不授权就手动填，不影响任何功能
- **趣味组合名**：根据实际商品生成「香辣丰盛组合」这类名字，
  只描述口味氛围，**绝不编造营养功效或限量信息**
- **预算严格不超**：金额全程用整数「分」计算，2000 次随机压力测试零超支
- **忌口真排除**：9 类忌口基于配料与品名关键词匹配，命中即从候选池移除
- **券自动匹配**：下单前自动领券，并用最新券重算实付价
- **单件重抽**：不满意只换一样，其余保留——控制感比「全部重摇」强得多
- **下单有三重防护**：全程只读，只有显式二次确认才下单；并发锁挡重复提交；失败不自动重试
- **无解也给方案**：抽不出来时会告诉你「把单品上限调到 X 元」而不是干巴巴报错
- **零依赖**：`git clone` 后直接 `node src/interfaces/cli.js`，不需要 `npm install`

## 快速开始

### 环境要求

- Node.js >= 20（用到内置 `fetch`）
- 麦当劳 MCP Token（[申请地址](https://open.mcd.cn/mcp)，手机号登录 → 控制台 → 激活）

### 方式一：网页版（推荐）

**Token 两种配置方式，选一种：**

```bash
# 方式 A（推荐）：一条命令写好，不用手动建文件
node src/interfaces/cli.js set-token 你的Token

# 方式 B：手动创建 .env，内容一行
#   MCD_MCP_TOKEN=你的Token

# 方式 C：当前终端的环境变量
export MCD_MCP_TOKEN="你的Token"        # bash
$env:MCD_MCP_TOKEN="你的Token"          # PowerShell
```

配置完自检一下，会告诉你 Token 读没读到、从哪个文件读的：

```bash
node src/interfaces/cli.js doctor
```

> **为什么要专门给一条 `set-token` 命令**：在 Windows 上手动创建 `.env`
> 很容易失败——资源管理器不允许以点开头的文件名，记事本另存时又会自动补
> `.txt` 后缀，结果就是 Token 怎么都读不到。程序已兼容 `.env` / `.env.local` /
> `.env.txt` / `mcp-token.txt` 多个文件名，并会在 doctor 里打印搜索过的路径。
>
> **环境变量按进程生效**——你在 A 窗口设了，B 窗口（包括 IDE 内置终端、
> 自动化工具）读不到。多处使用的话，写文件更省事。
> `.env` 已加入 `.gitignore`，不会被提交。

**启动：**

```bash
npm start
```

浏览器打开 <http://localhost:5173>

**用法**：填好地点和预算 → 点拉杆（或直接按回车）→ 揭晓餐单 →
对某一项不满意点「重扭」只换那一项 → 满意后「确认这份搭配」。

音效默认关闭，机身左上角可开。系统开启「减少动态效果」时动画会自动关闭。

### 方式二：命令行

```bash
node src/interfaces/cli.js doctor                      # 环境自检
node src/interfaces/cli.js caps                        # 列出可设条件
node src/interfaces/cli.js spin --address="上海虹桥站" --budget=40
```

## 使用示例

### 基础：一句话设定条件

```bash
node src/interfaces/cli.js spin --address="上海虹桥站" --budget=40
```

```
门店：上海虹桥站麦当劳（120m）
菜单：68 样在售，忌口过滤后 61 样

扭出来了 ——
  1. 麦香鱼           23.00 元  汉堡类，先垫底，鱼
  2. 麦乐鸡块         19.00 元  小食类，配着吃，鸡肉
  3. 中可              4.00 元  饮料类，配着吃

合计 46.00 元 / 预算 50.00 元（用了 92%）
优惠券「满30减8」立减 8.00 元 → 实付约 38.00 元
营养合计：约 690 kcal，蛋白 32g（2/3 项有数据）
```

> 预算不够时会自动在同品类里找更便宜的平替；实在凑不出会明确告诉你调哪个参数。

### 忌口 + 饮食目标

```bash
node src/interfaces/cli.js spin --address="深圳南山科技园" --budget=60 --avoid=spicy,seafood --diet=light
```

`--avoid` 可选值：`spicy`（辣）、`pork`（猪肉）、`beef`（牛肉）、`chicken`（鸡肉）、
`seafood`（海鲜）、`dairy`（乳制品）、`gluten`（麸质）、`nuts`（坚果）、`onionGarlic`（葱蒜）
`--diet` 可选值：`none`（不设偏好）、`light`（轻食低卡）、`protein`（高蛋白）、`indulge`（解馋放纵）

### 必吃项

```bash
node src/interfaces/cli.js spin --address="上海虹桥站" --must="巨无霸,薯条" --budget=60 --save=r.json
```

必选项一定会出现在结果里，且**不受单品价格上限约束**——想吃就一定要吃到，
超预算了会直接告诉你，而不是偷偷换一个。

### 单件重抽

```bash
node src/interfaces/cli.js reroll --address="上海虹桥站" --slot=2 --from=r.json
```

只换第 2 样，其余保持不变。优先在同品类内换（同价位、同风格），
同品类没有其他可选时才跨品类替换。

### 确认搭配

```bash
node src/interfaces/cli.js confirm --address="上海虹桥站" --from=r.json
```

输出人话摘要 + 可直接提交给下单接口的订单 JSON。这一步**不产生任何订单**。

### 创建订单（可选）

确认无误后可以真正下单：

```bash
# 第一次执行只展示将要下单的内容，不会真下单
node src/interfaces/cli.js order --address="上海虹桥站" --from=r.json

# 确认无误后加 --yes
node src/interfaces/cli.js order --address="上海虹桥站" --from=r.json --yes
```

下单前会自动领券并用最新券重算价格，然后返回订单号和**麦当劳官方返回的支付链接**，
支付由你自己在官方渠道完成。

> **三重防护**：扭蛋 / 重抽 / 揭晓全程只读，只有显式执行 `order --yes`
> 才会下单；网页端必须先在确认页看过内容才能点「确认下单」，
> 且每次重新扭蛋都会作废这个确认；后端有「在途锁 + 成功后 3 分钟冷却锁」，
> 实测连续点击 4 次只会真正下单 1 次。
> 下单失败**不会自动重试**，避免重复下单。

### 作为 WorkBuddy / 其他 MCP 客户端使用

把麦当劳 MCP 配置到你的客户端（Cherry Studio / Cursor / Trae / WorkBuddy 等），
然后直接说：

> 帮我找上海虹桥站附近 40 块以内的麦当劳搭配，不要辣，要低卡

详见 [mcp-config.example.json](mcp-config.example.json) 与
[MCP_INTEGRATION.md](MCP_INTEGRATION.md)。

## 命令行参数

| 参数 | 说明 | 默认值 |

| `--budget` | 总预算（元） | 40 |
| `--itemMax` | 单品价格上限（元） | 30 |

## 项目结构

采用**六边形架构**，把「业务规则」和「外部接口」彻底隔开——
这样算法可以脱离网络离线测试，麦当劳 MCP 改字段也不会波及抽签逻辑。

```
src/
├── domain/            领域层：纯函数，零 I/O，可离线测试
│   ├── catalog.js       菜单索引、品类归类、忌口过滤规则
│   ├── gacha.js         抽签引擎（加权随机 + 定向修复 + 预算约束）
│   ├── reveal.js        单件重抽、确认搭配
│   ├── naming.js        趣味组合名生成（有产品红线约束）
│   └── cityLocator.js   经纬度 → 城市名（内置城市中心点表，离线可用）
├── infra/             基础设施层：与麦当劳 MCP 打交道
│   ├── env.js           读取项目 .env（零依赖 dotenv）
│   ├── mcdMcpClient.js  零依赖 MCP 客户端（Streamable HTTP + JSON-RPC）
│   └── mcdAdapter.js    把 MCP 各接口的返回收敛成统一领域模型
├── app/               用例层：编排 I/O 与缓存
│   └── gachaService.js  找店→拉菜单→拉券→抽签，含参数归一化与下单锁
└── interfaces/        接入层
    ├── cli.js           命令行
    ├── httpServer.js    零依赖 HTTP 服务
    └── web/             网页 UI（原生 HTML/CSS/JS）
        ├── index.html
        ├── style.css
        ├── machine.css    扭蛋机机身、扭蛋球、拉杆、胶囊动画
        └── app.js
```

依赖方向严格向内：`interfaces → app → domain`，`infra` 通过 `app` 注入 `domain`。
领域层不 import 任何网络或 MCP 相关代码。

## 设计要点

### 为什么手写 MCP 客户端

麦当劳 MCP 用的是 Streamable HTTP，协议层就是「POST 一个 JSON-RPC 请求体到
`https://mcp.mcd.cn`」。用官方 SDK 需要处理采样、roots、传输协商等一大堆本项目
用不到的能力，而这份代码要**让评审 clone 完就能跑**，多一个 `npm install`
就多一份失败可能。所以客户端只有 200 行，零依赖。

实现要点：按规范先发 `initialize` 握手拿 sessionId；通知类请求返回
`202 Accepted` 无 body，要单独处理；服务端可能返回纯 JSON 也可能返回
SSE 帧，两种都要能解析；对 429 和 5xx 做指数退避重试。

### 为什么抽签用「随机 + 修复」而不是穷举

菜单 60+ 项时，组合数是指数级的，穷举不可行。
更重要的是——**抽蛋机的手感就是随机但有惊喜**，纯穷举会失去产品灵魂。

算法分三步：锁定必选项 → 加权随机填充 → 定向修复（放不下就找同品类更便宜的平替）。
多样性、饮食目标、预算利用率通过权重函数影响随机分布，而不是写成硬规则。

加权随机接入了可复现的 `rng` 注入，所以「同一种子必得同一结果」——
这是算法能被测试的前提。

### 金额为什么全程用分

浮点数算钱必然出问题。整个项目只有 `priceCents` 一个金额单位，
入口做「元 → 分」转换后就再不碰浮点。压力测试断言 `totalCents <= budgetCents`
2000 次零失败。

### 忌口为什么用关键词规则

麦当劳没有「无麸质」这样的结构化忌口字段，辣、蒜、洋葱这些只体现在配料和
品名里。所以用关键词规则匹配，命中任一即排除。规则表放在 `catalog.js`
而不是配置文件，因为它属于业务语义、需要版本管理和评审。

### 定位为什么只做到「城市」这一级

浏览器 `geolocation` 给的是经纬度，但麦当劳 `query-nearby-stores` **不认经纬度**——
实测把 `31.19,121.32` 填进 keyword，服务端直接回「没有查询到该地址」。
它要的是「纯城市名 + 位置关键词」两个字段。

要拿到城市名，常规做法是调高德/百度的逆地理编码，但那需要密钥，
会破坏「零依赖、clone 即跑」。所以这里内置了一张城市中心点坐标表
（`src/domain/cityLocator.js`，约 60 个城市），用球面距离找最近的。

**代价是精度**：判断的是「离哪个城市中心最近」，两城交界处可能选错。
所以功能设计上做了三件事，而不是假装很准：

1. 定位结果只**预填**到输入框，用户可以随手改
2. 距离超过 15 公里会显示实际距离，超过 60 公里直接提示「建议手动填写」
3. 定位失败（拒绝授权 / 超时 / 非 HTTPS）一律降级为手动输入，不阻断主流程

定位按钮是**可选增强**：不点它，手动输入「上海虹桥站」一样能用，
而且手动补上地标后，返回的门店通常更近。

## 测试

```bash
npm test
```

51 项测试全部基于 Node 内置 `node:test`，不依赖任何测试框架。

覆盖重点：

- 预算约束：200 次随机 + 2000 次压力测试，金额零超支
- 忌口过滤：单规则、多规则叠加、过滤后菜单不为空
- 可复现性：同种子同结果，不同种子不同结果
- 趣味名红线：遍历多组搭配，断言不含功效声称、限量、中奖字样
- 下单安全：在途拦截、冷却拦截、冷却过期放行、失败后锁释放、内部字段不泄漏
- 兜底路径：必选项超预算、菜单被过滤空、营养数据缺失、券门槛不够
- 重抽语义：只改指定槽位、真的换掉东西、换不了时明说
- 定位推断：市中心坐标能推断正确城市、距离量级合理、
  10 种「能转成 0 但实际无效」的入参一律判无效、离所有城市过远时明确提示手动填写

## 当前限制

以下是**尚未完成或有意不做**的部分，不会在文档里假装已完成：

**唯一未验证的链路**
- `create-order` 的真实下单。参数名已按 `tools/list` 的 schema 校准
  （`storeCode / orderType / beType / items[{productCode, quantity}] / takeWayCode`），
  但它会创建真实订单，所以留到用户实际点单时再验证，不在文档里假装已跑通。

**受上游能力限制**
- 定位只能到城市级：麦当劳 MCP 不接受经纬度，也不返回门店坐标（实测
  `longitude/latitude` 恒为 0），因此无法按真实距离排序门店。
  补上具体地标（如「上海虹桥站」）会让结果明显更准。
- 门店查询每次最多返回 5 家，这是服务端行为。

**第一版有意不做**
- 多人点餐（拼单、AA 分摊）
- 积分兑换、积分抽奖
- 外送配送（仅到店取餐）
- 自动付款（只跳转到官方支付链接）
- 账号注册与长期饮食管理
- 分享卡导出 PNG

**已知限制**
- 扭蛋动画为 CSS 实现（拉杆下压 + 胶囊滚落），
  效果偏克制，没有物理引擎级的拟真手感
- 忌口基于关键词规则匹配，**不能保证无过敏原**。麦当劳 MCP 未提供结构化的过敏原字段，
  无法核验的成分条件不视为已满足
- 抽签在**单品粒度**上进行。套餐子商品的替换需 MCP 明确支持替换选项才可能实现，
  第一版以完整可售商品为替换单位
- 会话状态存在服务进程内存中，服务重启后需重新扭蛋
